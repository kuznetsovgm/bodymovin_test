# Платформа анимированных текстовых стикеров — описание проекта (rewrite с нуля)

> Статус: проектное описание (spec). Дата: 2026-06-10.
> Назначение: зафиксировать **что** разрабатываем — продукт, функционал и возможности — для полного переписывания с нуля. Документ не привязан к текущему коду; существующая реализация служит лишь источником требований.

---

## 1. Обзор и цели

Платформа для создания и распространения **анимированных текстовых стикеров** в Telegram. Ключевая идея: пользователь не рисует один конкретный стикер, а создаёт **переиспользуемый шаблон** анимаций и эффектов для текста. Текст подаётся отдельно — в **inline-режиме** бота, — и платформа рендерит шаблон с этим текстом в формат Telegram (`.tgs`).

### Цели

- **Гибкий редактор** уровня простых мобильных видеоредакторов: таймлайн, слои, перетаскивание/тримминг, живой превью.
- **Оптимизация размера**: гарантированно укладывать результат в лимит Telegram **`.tgs` ≤ 64 KB** за счёт слияния слоёв/контуров и сглаживания (симплификации) геометрии.
- **Пользовательские шаблоны** с приватностью, публичной галереей, рейтингом и модерацией.
- **Многоязычность** и корректная типографика (шейпинг, RTL/bidi, пер-скрипт фоллбек шрифтов).
- **Детерминированность** рендера (один и тот же шаблон + текст + seed → идентичный результат).

### Что НЕ входит (YAGNI на старте)

- Растровые изображения как слои (Telegram `.tgs` запрещает растровые ассеты).
- Экспорт в видео/GIF и в «сырой» Lottie JSON (можно добавить позже; в первой версии — только Telegram `.tgs` и custom emoji/статика).
- Совместное редактирование в реальном времени (multiplayer).
- Звук.

## 2. Продуктовая модель

### Сущности

- **Шаблон (Template)** — декларативное описание сцены: слои, их трансформации, анимации-клипы на таймлайне, привязки текста, параметры экспорта. Главный артефакт, который создаёт пользователь.
- **Текстовый ввод (TextInput)** — строка(и), которые пользователь подаёт в inline. Разбивается на N полей по разделителю/переносу строки и подставляется в динамические текстовые слои шаблона.
- **Рендер (Render)** — результат `Template + TextInput → Lottie → .tgs`. Кэшируется по хешу.
- **Публикация (Listing)** — шаблон, опубликованный в общую галерею; имеет рейтинг и статус модерации.

### Поток ценности

```
[Редактор]  ── создаёт ──▶  Шаблон (приватный)
                                  │
                          (опц.) публикация
                                  ▼
                          Публичная галерея ── рейтинг/модерация
                                  │
[Inline: @bot текст] ── подбор шаблонов (свои + избранные/публичные)
                                  ▼
                    Рендер шаблона с текстом → .tgs → галерея результатов
                                  ▼
            Пользователь выбирает → отправка в чат / добавление в стикерпак
```

### Видимость шаблонов

- Приватные по умолчанию.
- Пользователь может опубликовать шаблон в общую галерею.
- В галерее — рейтинг (оценки/использования) и модерация: **post-moderation** (после публикации), реактивно по жалобам или по падению рейтинга.
- В inline пользователю показываются его собственные шаблоны + избранные/закреплённые публичные.

### Привязка текста (text binding)

- Каждый текстовый слой шаблона помечен как **static** (фиксированный текст в шаблоне) или **dynamic** (заполняется из inline-ввода).
- Динамических полей может быть **несколько**; inline-текст разбивается по заданному в шаблоне разделителю (символ или перенос строки) и распределяется по динамическим слоям по порядку.
- Поведение при несовпадении количества: лишние поля остаются пустыми/скрываются; недостающий ввод → слой не рендерится (правила фиксируются в схеме шаблона).

## 3. Пользовательские сценарии

1. **Создание шаблона.** Юзер открывает редактор (Mini App), добавляет текстовый слой (динамический), вешает эффекты (например, «волна» + «радуга»), добавляет фон-плашку, настраивает таймлайн и длительность, видит живой превью и индикатор размера, сохраняет.
2. **Использование своего шаблона.** В любом чате: `@bot Привет` → бот показывает варианты по тексту «Привет» из шаблонов юзера → выбор → отправка.
3. **Несколько полей.** Шаблон с двумя динамическими блоками и разделителем `|`: `@bot Верх|Низ` → верхний и нижний текст.
4. **Публикация и галерея.** Юзер публикует шаблон; другие находят его в галерее, добавляют в избранное, используют в своём inline.
5. **Модерация.** Жалоба на публичный шаблон → попадает в очередь модерации (расширенная веб-версия редактора/админки) → скрытие/бан при нарушении.
6. **Стикерпак.** Из результата рендера — добавление в личный анимированный стикерпак Telegram.

## 4. Архитектура (подсистемы)

Система делится на 5 подсистем со строгими границами. Каждая на этапе реализации становится отдельным под-проектом (свой spec → plan → имплементация).

```
┌─────────────────────────────────────────────────────────────┐
│                      Render Engine (TS)                      │  ← общий пакет
│  шрифты · шейпинг · layout · glyph→bezier · анимации ·       │     (Node + браузер)
│  кривой текст · фоны · композиция → Lottie (богатый)         │
└───────────────┬───────────────────────────┬─────────────────┘
                │                           │
        ┌───────▼────────┐         ┌────────▼─────────┐
        │   Optimizer    │         │     Editor       │  (React)
        │ merge·smooth·  │         │ ядро + Mini App  │
        │ compress·budget│         │   + web-оболочка │
        └───────┬────────┘         └──────────────────┘
                │ .tgs ≤ 64KB
        ┌───────▼──────────────────────────────────────┐
        │              Backend (NestJS)                 │
        │  templates · gallery · rating · moderation ·  │
        │  render-service (workers) · assets · storage  │
        │       Postgres + Redis + Telegram upload      │
        └───────┬───────────────────────────────────────┘
                │
        ┌───────▼────────┐
        │ Bot / Inline   │  (NestJS-модуль, Telegraf)
        │ gateway        │
        └────────────────┘
```

**Принцип изоляции:** Render Engine и Optimizer не знают про Telegram, HTTP и БД — это чистые функции над данными. Это даёт переиспользование (сервер + браузер), тестируемость и предсказуемость.

## 5. Render Engine (ядро)

Чистый TS-пакет. Главная функция: `render(template, textInput, options) → LottieDocument`. Без побочных эффектов; весь рандом — через seed.

### 5.1 Шрифты и типографика

- Загрузка TTF/OTF (кэш по пути/хешу), работа с контурами глифов.
- **Шейпинг** через HarfBuzz (лигатуры, kerning, marks) — для корректной раскладки сложных письменностей.
- **Bidi/RTL**: определение направления, разбиение на ран-ы, корректный порядок.
- **Пер-скрипт фоллбек шрифтов**: latin, cyrillic, arabic, han, georgian, hebrew, devanagari, emoji и др.; настраиваемые глобальные и пер-шаблонные фоллбеки.
- Проверка поддержки символов шрифтом (для предупреждений в редакторе).

### 5.2 Раскладка (layout)

- Авто-подбор размера шрифта под холст (по площади/габаритам).
- Перенос длинных строк, многострочная раскладка.
- Авто-вписывание в кадр (итеративное уменьшение до попадания в безопасную область).
- Единицы анимации: символ / графемный кластер (важно для emoji и сложных скриптов).

### 5.3 Геометрия

- Конвертация контуров глифа в безье-пути Lottie.
- **Кривой текст**: режимы `arc` (по дуге) и `sphere` (сферическая проекция с перспективным масштабированием и поворотом букв); параметры — радиус, edge-drop, диапазоны, поворот букв.

### 5.4 Каталог анимаций (расширяемый реестр)

Анимации — независимые модули, регистрируемые в реестре; добавление новой не требует правок ядра. Каналы:

- **Transform (слой/группа):** Slide, ScalePulse, Rotate, Shake, Bounce, Vibrate, Skew (+ задел под новые).
- **Color (заливка) / Stroke:** CycleRGB, Rainbow, Zebra, Chase + статика; пофазовый сдвиг по буквам/элементам.
- **Letter (по-буквенно):** Vibrate, TypingFall, Wave, ZigZag, Rotate, SnakeScale.
- **PathMorph (искажение контура):** Warp, WarpAiry, SkewPulse, SkewSwing.

### 5.5 Композиция анимаций

- Несколько анимаций в одном канале комбинируются через **композиторы**: additive / blend(вес) / priority / timeline(окно).
- У каждого клипа: тип, параметры, окно по времени `[start,end]`, приоритет, фаза.
- Детерминированность: `seed` глобальный + производный пер-букве/контуру.

### 5.6 Слои сцены

- **Текстовые слои** (несколько; static/dynamic), каждый со своими шрифтом, стилем, анимациями, трансформом, кривизной.
- **Фоны/фигуры:** Solid (плашка), Frame (рамка), Stripes (полосы), GlyphPattern (сетка глифов), TextLike (вторичный текст), Knockout (вырез по форме текста, even-odd) + простые векторные фигуры.
- **Векторные стикеры/эмодзи** из библиотеки — как слои, с анимациями.
- У каждого слоя: трансформ (scale/rotate/opacity/offset), порядок (z), набор анимаций-клипов.

### 5.7 Выход

Engine возвращает **«богатый» Lottie** (максимально выразительный, без оглядки на размер). Сжатие — задача Optimizer.

## 6. Optimizer (выходной конвейер) — фокус оптимизации

Назначение: превратить богатый Lottie в минимальный валидный `.tgs` под бюджет **≤ 64 KB**, сохранив визуальную суть.

### 6.1 Слияние слоёв и контуров (merge)

- **Статический текст** (без по-буквенной анимации): boolean-union всех контуров глифов в **один путь + одна заливка** — основной выигрыш по размеру и узлам.
- **По-буквенно-анимированный текст**: union контуров в пределах буквы (один путь на букву), общий стиль-слой на группу.
- **Фоны**: схлопывание перекрывающихся плашек/рамок; вынос общих стилей.
- Двухрежимность фиксируется автоматически по наличию per-letter анимаций (развилка В из обсуждения).

### 6.2 Сглаживание / симплификация (smooth)

- Фитинг безье / RDP-упрощение контуров с контролем погрешности.
- Слияние углов и стыков на границах букв при union — убирает швы/артефакты и снижает число точек.
- Контролируемый порог: размер vs. визуальная точность.

### 6.3 Сжатие анимации и сериализации (compress)

- Удаление избыточных и дублирующих ключевых кадров, схлопывание hold-сегментов.
- Квантование времени и координат, округление чисел до нужной точности.
- Срезание дефолтных полей Lottie (как в текущем минификаторе), дедуп путей/стилей.
- gzip → `.tgs`.

### 6.4 Budget-aware degrade

- Оценка итогового размера до финальной сериализации.
- При превышении — **прогрессивная деградация** по приоритетам: точность путей → плотность ключей → fps → отключение наименее заметных эффектов, до попадания в бюджет.
- Результат деградации сообщается в редактор (что и насколько урезано).

### 6.5 Контракт с редактором

- **Живой индикатор размера** (KB) в редакторе на каждом изменении.
- Предупреждения: «шрифт не поддерживает символы», «превышен бюджет — будет упрощено», «слой не виден».

## 7. Editor (React)

Архитектура: **общее ядро редактора** + две оболочки — **Telegram Mini App** (основная, мобильный UX) и **расширенная веб-версия** (админы/модерация).

### 7.1 Холст и таймлайн (UX как в простых мобильных видеоредакторах)

- **Холст**: превью сцены 512×512, прямое манипулирование слоями (перемещение/масштаб/поворот), safe-зоны.
- **Таймлайн**: дорожки по слоям; клипы-эффекты с началом/концом; drag/trim/resize; перетаскивание между дорожками; scrub-ползунок; play/pause/loop.
- **Превью** рендерится движком (в браузере; тяжёлые части — через WASM, напр. HarfBuzz) — то, что видит юзер, совпадает с финалом.

### 7.2 Модель анимации (гибрид)

- **Базовый режим**: каталог готовых эффектов-клипов с параметрами (слайдеры min/max/step) — навешиваются на слой, комбинируются, тримятся.
- **Продвинутый режим**: ручные ключевые кадры по свойствам (позиция/масштаб/поворот/цвет) с easing — поверх той же модели.
- Оба режима пишут в единую декларативную схему шаблона.

### 7.3 Слои и библиотеки

- Добавление слоёв: текст (static/dynamic), фоны/фигуры, векторные стикеры/эмодзи из библиотеки.
- Панель свойств слоя: шрифт, цвет/обводка, трансформ, кривизна текста, привязка текста (static/dynamic, разделитель).
- Выбор шрифта с проверкой поддержки введённого текста; просмотр глифов шрифта.

### 7.4 Сервисные функции

- Индикатор размера `.tgs`, предупреждения оптимизатора.
- Сохранение/версии шаблона, дублирование, превью с тестовым текстом.
- Публикация в галерею (с превью и тегами).

## 8. Модель данных шаблона (schema)

Хранится **собственная декларативная схема** (не Lottie). Lottie — лишь выходной артефакт. Это даёт гибкое редактирование и работу оптимизатора (развилка Б).

Концептуальная структура:

```
Template {
  id, ownerId, version, meta { name, tags, visibility, createdAt }
  canvas { width=512, height=512, fps, durationFrames }
  textBinding { separator: char|newline, fields: [{ slotId, order }] }
  layers: [
    Layer {
      id, type: text|background|shape|sticker,
      z, transform { pos, scale, rotation, opacity, anchor },
      // для text:
      text?: { mode: static|dynamic, value?|slotId, font, style{fill,stroke}, curve },
      // для background/shape/sticker:
      content?: { ... типоспецифичные параметры ... },
      clips: [ AnimationClip {
        channel: transform|color|stroke|letter|pathMorph,
        type, params, window{start,end}, compose, priority, phase
      } ],
      keyframes?: [ ManualKeyframe { prop, t, value, easing } ]  // продвинутый режим
    }
  ]
  export { format: tgs|emoji, sizeBudgetKB: 64, seed }
}
```

- `seed` хранится в шаблоне (в блоке `export`), но **используется Render Engine** для детерминизма (§5.5), а не только при экспорте.
- Схема версионируется (миграции при эволюции формата).
- Валидация на входе движка/бэкенда.

## 9. Backend (NestJS)

Модули:

- **Templates** — CRUD, версии, дублирование, валидация схемы.
- **Gallery** — публикация, листинги, поиск/теги, избранное.
- **Rating** — оценки/счётчики использования, агрегированный рейтинг.
- **Moderation** — очередь, жалобы, скрытие/бан, аудит-лог.
- **Render Service** — пул воркеров (worker threads/процессы), очередь задач, кэш результатов; вызывает Engine + Optimizer.
- **Assets** — шрифты, библиотека стикеров/эмодзи, фоллбеки.
- **Telegram Integration** — загрузка `.tgs` в storage-чат для получения `file_id`, работа со стикерпаками/emoji.
- **Auth/Users** — идентификация через Telegram (Mini App initData), профили. **Является предусловием** для Bot (§10) и Mini App-редактора (§7): должен быть готов раньше них (учтено в порядке §14, шаг 3 до 4–5).

Хранилища:

- **Postgres** — пользователи, шаблоны, версии, галерея, рейтинги, модерация.
- **Redis** — кэш рендеров (file_id по хешу `template+text+optVersion`), очереди задач, inline-история, дебаунс, горячие конфиги.

Наблюдаемость:

- Метрики (Prometheus): rate/latency inline, длительность рендера по каналам, cache hit/miss, размеры на выходе, ошибки, состояние воркеров/Redis.
- Логи (структурные), дашборды.

## 10. Bot / Inline Gateway

- **Inline-запрос**: `@bot текст` → дебаунс → разбор текста по разделителю → подбор шаблонов → рендер/кэш → галерея результатов с пагинацией.
- **Базис подбора (intent):** показываются собственные шаблоны пользователя + добавленные в избранное публичные. Текст **только заполняет поля** шаблонов, а не фильтрует их (никакого текстового матчинга). Порядок — по недавности/избранности; точная схема ранжирования фиксируется в spec под-проекта Bot.
- **Кэш**: повторный текст+шаблон отдаётся мгновенно по `file_id`.
- **Команды/кнопки**: открыть редактор (Mini App), мои шаблоны, история, добавить в стикерпак.
- **История**: недавно использованные результаты пользователя.

---

## 11. Галерея, рейтинг, модерация

- **Публикация**: приватный шаблон → публичный листинг (превью, теги, автор).
- **Рейтинг**: на основе оценок и/или частоты использования; влияет на ранжирование и на триггеры модерации.
- **Модерация (post-moderation)**: реактивная — по жалобам и по падению рейтинга; действия — скрыть/вернуть/забанить; аудит.
- **Инструменты**: расширенная веб-версия редактора включает админ/модератор-панель (очередь, фильтры, статистика).

## 12. Экспорт и дистрибуция

- **Telegram анимированный `.tgs`** (основной): валидная структура под ограничения Telegram, ≤ 64 KB; добавление в стикерпак и отдача в inline.
- **Telegram custom emoji / статика**: `.tgs` 100×100 для emoji и/или статичные webp.
- Форматы — параметр экспорта шаблона; видео/GIF/Lottie-JSON — вне scope первой версии.

### Ограничения Telegram (учитываются Optimizer'ом)

- Размер `.tgs` ≤ 64 KB; холст 512×512 (emoji 100×100); fps ≤ 60; длительность ≤ 3 c.
- Только векторные фигуры; запрещены растровые ассеты, ряд эффектов/режимов наложения, выражения.

---

## 13. Нефункциональные требования

- **Размер**: гарантия ≤ 64 KB через бюджет-деградацию; целевой типовой размер существенно ниже.
- **Производительность рендера**: приемлемая латентность inline (кэш + воркеры); плавный превью в редакторе.
- **Детерминированность**: одинаковый вход → одинаковый выход (seed).
- **Многоязычность**: корректная типографика для основных письменностей и emoji.
- **Расширяемость**: новые анимации/фоны/эффекты — через реестр, без правок ядра.
- **Тестируемость**: чистые движок и оптимизатор покрываются модульными тестами (layout, композиторы, merge/smooth, бюджет).
- **Наблюдаемость**: метрики/логи на всех ключевых путях.

## 14. Декомпозиция на под-проекты и порядок

Рекомендуемый порядок реализации (каждый — отдельный spec → plan):

1. **Render Engine** (фундамент; даёт богатый Lottie из схемы шаблона). Включает шрифты/шейпинг/layout/анимации/слои.
2. **Optimizer** (merge/smooth/compress/budget) — поверх Engine; ключевая цель проекта.
3. **Backend core** (Templates, Render Service, Assets, Auth, хранилища).
4. **Bot / Inline Gateway** (доставка ценности; быстрый видимый результат поверх 1–3).
5. **Editor** (ядро + Mini App), затем веб-оболочка.
6. **Gallery / Rating / Moderation** (социальный слой).
7. **Наблюдаемость/инфраструктура** (поперечно, наращивается по ходу).

> Порядок допускает вертикальный срез: минимальный Engine → минимальный Optimizer → backend+bot с одним зашитым шаблоном → редактор, затем расширение каждого.
